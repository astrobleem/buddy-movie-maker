## Realtime regression

A user report exposed an MMTIME units error that the short submission checks
had not caught. The old conversion requested TIME_SAMPLES (2), but divided by
bytes per second, making the video/counter clock half speed. TIME_BYTES (4) also
had the inverse wrong divisor. Microsoft SDK `mmsyscom.h` defines these units;
the corrected conversion uses named constants and handles samples, bytes and
milliseconds independently, with three new regression assertions.

An instrumented before build using the old conversion advanced 14,957 movie ms
in 30,013 wall ms (ratio 0.49835). Raw device counts advanced 717,948 frames,
about 23,921 frames/second for the declared 24 kHz mono PCM16 format. The PCM
render itself took 937 ms for a 72-second synthetic movie, before playback began.
The problem was clock conversion, not a two-times-long audio queue or slow
synthesis. That before run deliberately reports a pacing failure.

The corrected conversion's initial 30-second run advanced 29,907 movie ms in
30,011 wall ms (ratio 0.99653), with maximum drift 125 ms, mostly device startup.
Longer pacing evidence and lifecycle checks are generated by `--pace-test`.
This check samples the actual Player/waveOut pipeline against Stopwatch wall
time and records raw clock units/counts, monotonicity, drift and timed pause,
seek, backward seek, end and replay. It is separate from headless CI.

The final candidate passed a 60-second run: 59,906 movie ms in 60,007 wall ms
(ratio 0.99832), monotonic, maximum drift 132 ms. The device advanced 1,437,752
frames, about 23,960 frames/second. Pause stayed frozen for 500 ms. Forward seek
advanced 4,893 ms in 5,004 wall ms; backward seek 4,920 ms in 5,009 wall ms;
replay 4,923 ms in 5,013 wall ms, all monotonic. The final 1,000 ms segment
completed and stopped in 1,085 wall ms. The test reports PASS for real-time
pacing and lifecycle. Headless format/synthesis checks also passed (32 checks),
as did the full local suite (41 checks) and four private local movie checks.
The specific movie from the user regression report has not been identified;
available private local movies were shorter than the timing-test minimum.
